Generated by `phx.gen.auth`. Handles all authentication and user management.

## Modules

### `Shepherd.Accounts` (context module — `lib/shepherd/accounts.ex`)

The public API for all auth operations. Delegates to `User`, `UserToken`, and `UserNotifier` internally. Uses `Shepherd.Repo` for all persistence.

**Public functions:**

| Function | Description |
|---|---|

| `get_user_by_email_and_password(email, password)` | Looks up user and verifies password. Returns `%User{}` or `nil`. Guards on binary args. |
| `get_user!(id)` | Fetches user by ID. Raises `Ecto.NoResultsError` if not found. |

| `change_user_email(user, attrs \\ %{}, opts \\ [])` | Returns an `Ecto.Changeset` for email changes (for form rendering). |
| `update_user_email(user, token)` | Verifies a change-email token, updates the email, deletes related tokens. Wrapped in `Repo.transact/1`. Returns `{:ok, user}` or `{:error, :transaction_aborted}`. |
| `change_user_password(user, attrs \\ %{}, opts \\ [])` | Returns an `Ecto.Changeset` for password changes (for form rendering). |
| `update_user_password(user, attrs)` | Validates and hashes new password, updates user, deletes ALL user tokens. Returns `{:ok, {user, expired_tokens}}` or `{:error, changeset}`. |

| `deliver_login_instructions(user, url_fun)` | Generates a hashed email token with context `"login"` and sends login/confirmation instructions via `UserNotifier`. |
| `delete_user_session_token(token)` | Deletes the session token from DB. Returns `:ok`. |

**Private helpers:**
- `update_user_and_delete_all_tokens/1` -- Transactionally updates a user changeset, then fetches and deletes all `UserToken` records for that user. Returns `{:ok, {user, expired_tokens}}`.

### `Shepherd.Accounts.User` (schema -- `lib/shepherd/accounts/user.ex`)

**Schema fields:**

| Field | Type | Notes |
|---|---|---|

| `confirmed_at` | `:utc_datetime` | Set when user confirms via magic link. `nil` for unconfirmed. |
| `authenticated_at` | `:utc_datetime` | Virtual field, populated from session token's `authenticated_at`. Not persisted. |
| `inserted_at` | `:utc_datetime` | Auto-managed by Ecto timestamps |
| `updated_at` | `:utc_datetime` | Auto-managed by Ecto timestamps |

**Public functions:**

| Function | Description |
|---|---|
| `email_changeset(user, attrs, opts \\ [])` | Casts and validates email. Options: `:validate_unique` (default `true`). Validates format (`@` required, no spaces), max length 160, uniqueness, and that email actually changed. |
| `password_changeset(user, attrs, opts \\ [])` | Casts and validates password. Options: `:hash_password` (default `true`). Validates confirmation match, required, length 12-72 chars (72 bytes max for bcrypt). Hashes with `Bcrypt.hash_pwd_salt/1` and clears plaintext. |
| `confirm_changeset(user)` | Sets `confirmed_at` to current UTC time (truncated to second). |
| `valid_password?(user, password)` | Verifies password against `hashed_password` using `Bcrypt.verify_pass/2`. Calls `Bcrypt.no_user_verify/0` for nil user or missing hash to prevent timing attacks. |

**Changeset conventions:**
- `email_changeset` is used for both registration and email changes. Registration creates a user with email only (no password required).
- `password_changeset` is separate from email -- password is optional at registration time.
- `validate_email_changed/1` prevents no-op email updates by checking `get_change/2`.
- Uniqueness is enforced at both application level (`unsafe_validate_unique`) and DB level (`unique_constraint`).

| Field | Type | Notes |
|---|---|---|

| `token` | `:binary` | Raw bytes for session tokens, SHA-256 hash for email tokens |
| `context` | `:string` | `"session"`, `"login"`, or `"change:<email>"` |
| `sent_to` | `:string` | Email address the token was sent to (email tokens only) |

**Constants:**

| Constant | Value | Purpose |
|---|---|---|
| `@hash_algorithm` | `:sha256` | Hash algorithm for email tokens |
| `@rand_size` | `32` | Bytes of randomness for token generation |
| `@magic_link_validity_in_minutes` | `15` | Magic link expiry |

| `@session_validity_in_days` | `14` | Session token expiry |

**Public functions:**

| Function | Description |
|---|---|
| `build_session_token(user)` | Generates a 32-byte random token (stored raw, not hashed). Copies `user.authenticated_at` into the token record (falls back to `DateTime.utc_now(:second)`). Returns `{token_binary, %UserToken{}}`. |
| `verify_session_token_query(token)` | Returns `{:ok, query}` that joins user, checks expiry (14 days), and selects `{user_with_authenticated_at, inserted_at}`. |
| `build_email_token(user, context)` | Generates a 32-byte random token, hashes it with SHA-256 for DB storage, Base64-URL-encodes the raw token for delivery. Returns `{encoded_token, %UserToken{}}`. |
| `verify_magic_link_token_query(token)` | Decodes Base64, hashes, looks up by token+context `"login"`, checks 15-min expiry AND `sent_to == user.email`. Returns `{:ok, query}` or `:error`. |
| `verify_change_email_token_query(token, context)` | Same pattern as magic link but for `"change:*"` context with 7-day expiry. Returns `{:ok, query}` or `:error`. |

**Token strategy (two types):**
1. **Session tokens** -- Raw random bytes stored directly in DB. Looked up by exact match. Signed/stored in cookie by Phoenix. Valid for 14 days from creation.
2. **Email tokens (magic link, change-email)** -- Raw token is Base64-URL-encoded and sent to user via email. SHA-256 hash is stored in DB. Verified by hashing the decoded token and matching. This means DB read access alone cannot forge tokens.

## Auth Features

- **Passwordless registration**: `register_user/1` creates users with email only (no password required)
- **Email/password login**: Via `get_user_by_email_and_password/2` with bcrypt verification
- **Magic link (passwordless) login**: Email token with 15-minute expiry, one-time use
- **Email change flow**: Token-based with 7-day expiry, scoped to original email via `"change:<email>"` context
- **Password management**: Separate from registration, validates 12-72 chars, bcrypt hashing
- **Session management**: 14-day session token validity
- **Sudo mode**: 20-minute window from last authentication (configurable via second arg)
- **Token invalidation**: Password changes and first-time confirmation delete ALL user tokens
- **LiveView hooks**: `:mount_current_scope`, `:require_authenticated`, `:require_sudo_mode`

## Data Flow

### Registration and Confirmation
1. `register_user(%{email: email})` creates user with `email_changeset` (no password, `confirmed_at: nil`)
2. `deliver_login_instructions(user, url_fun)` generates a hashed `"login"` token and emails confirmation link
3. User clicks link, `login_user_by_magic_link(token)` confirms user (sets `confirmed_at`), deletes all tokens, returns user + expired tokens

### Magic Link Login (confirmed user)
1. `deliver_login_instructions(user, url_fun)` generates a hashed `"login"` token and emails magic link
2. User clicks link, `login_user_by_magic_link(token)` deletes the token record, returns `{:ok, {user, []}}`
3. Caller generates session token via `generate_user_session_token(user)`

### Session Lifecycle
1. `generate_user_session_token(user)` stores raw 32-byte token in DB with `authenticated_at`
2. Token stored in signed session cookie by Phoenix
3. On each request: `get_user_by_session_token(token)` verifies token, checks 14-day expiry, returns `{user, inserted_at}` with `authenticated_at` set on user struct
4. Logout: `delete_user_session_token(token)` removes from DB

### Email Change
1. `deliver_user_update_email_instructions(user, current_email, url_fun)` creates `"change:<current_email>"` token
2. User clicks link, `update_user_email(user, token)` verifies token, updates email, deletes all change tokens for that user+context

## Security Considerations

- **Bcrypt hashing**: Uses `Bcrypt.hash_pwd_salt/1` (default 12 rounds). Password max 72 bytes (bcrypt limitation).
- **Timing attack prevention**: `Bcrypt.no_user_verify/0` called when user not found or has no password, ensuring constant-time response.
- **Token randomness**: 32 bytes from `:crypto.strong_rand_bytes/1` (256 bits of entropy).
- **Email token hashing**: Tokens sent via email are SHA-256 hashed before DB storage. Raw token cannot be recovered from DB.
- **Session token storage**: Stored as raw bytes (not hashed) since they are kept in signed cookies, not sent via email.
- **Magic link expiry**: 15 minutes (intentionally short since email access = account access).
- **Change-email token expiry**: 7 days.
- **Session expiry**: 14 days from token creation.
- **Sudo mode window**: 20 minutes from last `authenticated_at` timestamp.
- **Session fixation prevention**: `login_user_by_magic_link/1` raises if an unconfirmed user has a password set (prevents magic link from bypassing password-based account security).
- **Token cleanup on sensitive changes**: `update_user_password/2` and first-time confirmation via magic link delete ALL tokens for the user.
- **Email scoping on magic link**: `verify_magic_link_token_query` checks `token.sent_to == user.email`, so tokens become invalid if the user's email changes.
- **Virtual fields redacted**: `password` and `hashed_password` are marked `redact: true`, excluded from `inspect` output.
